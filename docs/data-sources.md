# Production data source policy

This app should move from provisional demo-shaped data to production tournament data in a controlled way.

## Source priority

1. Official FIFA sources
2. Official host city / stadium sources
3. Trusted secondary sources for cross-checking only
4. Derived data generated by our own code

Official sources should be used for:

- group composition
- draw positions
- fixtures
- match numbers
- match dates
- kick-off local times
- venues
- knockout bracket structure

Trusted secondary sources may be used to find inconsistencies, but should not be the final authority for production fixture data.

## Current public facts to anchor the migration

The app's current structure still matches the tournament shape: 48 teams, 12 groups of four, 104 matches, 16 host cities, and a June 11 to July 19, 2026 tournament window.

Known group examples that should be verified against official sources before marking data official:

- Group A: Mexico, South Africa, South Korea, Czechia
- Group F: Netherlands, Japan, Sweden, Tunisia

These examples are useful as a migration guide, but the actual app data should only be marked `official` after checking the official FIFA schedule / group source.

## Data status rules

Use the existing `dataStatus` field carefully:

```txt
official
  The exact value was checked against an official source.

provisional
  The value is plausible or imported from a trusted secondary source, but has not been verified against the primary source.

placeholder
  The value exists only to keep the UI or type system working.
```

Do not mix these meanings.

## What counts as source data

Source data:

- countries
- group slots
- fixtures
- venues
- stadium names
- local kickoff times
- latitude / longitude, if taken from venue/stadium references

Derived data:

- map coordinates
- route segments
- travel distances
- total distance
- highlighted venues
- grouped match lists
- ViewModels

Derived data should be calculated or generated from source data, not hand-maintained.

## Runtime results

API-FOOTBALL is used only for runtime match-result updates through the Cloudflare Worker. It is not a
replacement for official static tournament facts such as fixtures, venues, groups, or kickoff local
times.

The Worker stores normalized result snapshots in KV. Browser code consumes those snapshots through
`/api/results`; it must not call API-FOOTBALL or expose provider keys. See
[Live Result Updates](live-result-updates.md).
